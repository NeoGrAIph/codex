# Subagent Workbench / agents overlay

## Feature passport

- Code name: `subagent-workbench`
- Status: переносимая fork-возможность; реализовывалась в нескольких release-ветках. В текущем `fork/140` реализован expanded observational-first перенос через native `/agent` picker: scan-first row summary, bounded team/status header, selected detail `Inspect`/`Actions`, prompt/context/plan/token/activity anchors, confirmed `interrupt one`, root/subtree-owner queue-only `send-message`, root/subtree-owner trigger-turn `follow-up` and confirmed `close one`.
- Goal: дать пользователю TUI-поверхность для наблюдения и переключения между sub-agents, вместо работы только через текстовые tool calls.
- Scope in: SAW/agents overlay как историческая цель feature; в текущем `fork/140` реализована `/agent` workbench-проекция со scan-first summary текущих agents, bounded preview prompt/context/activity, recovery detail, native watch/select, confirmed `interrupt one`, root/subtree-owner queue-only `send-message`, root/subtree-owner trigger-turn `follow-up` and confirmed `close one`.
- Scope out: сама модель исполнения sub-agent задач; historical `Ctrl+T` SAW hotkey parity, explicit connect UX, dismiss-only hiding, retry and stop-all actions до отдельного native contract.

## Как работает для пользователя

Пользователь видит TUI-окно со списком sub-agents, их статусами и контекстом. Польза: легче наблюдать за параллельной работой, переключаться между threads, queue-only отправлять сообщение из root или path-backed subtree-owner workbench, запускать follow-up turn для idle agent, подтверждённо прерывать один текущий turn и подтверждённо закрывать один spawned agent subtree без удаления replay/resume history.

## Implementation notes

Затрагивались TUI modules для overlay/window, routing/switching state, app event dispatch и docs. В поздних переносах возможность разнесена между `agents_overlay`, app state/routing и feature/project docs.

## Native coverage in rust-v0.140.0

Status: `partial, expanded locally`. Native release уже имеет `/agent`, `/subagents`, `AppEvent::OpenAgentPicker`, `AppEvent::SelectAgentThread`, agent ordering/switch labels, legacy `agent_status_feed` reference rendering и protocol event `SubAgentActivityEvent`. Текущий worktree расширяет existing `/agent` picker: header теперь показывает bounded agents status summary, row description показывает derived status/kind/path or short thread id, selected row показывает compact detail with status, current-view flag, kind, separated `Inspect` anchors, bounded prompt preview from app-server `Thread.preview`, stable `Created:`/`Updated:` timestamps from native `Thread.created_at`/`Thread.updated_at`, receiver-matched `Context:` from buffered `CollabAgentToolCall.prompt`, bounded `Plan:` anchor from latest per-thread `TurnPlanUpdated`, latest per-thread token usage when available, bounded recent activity from `ThreadEventStore`, separated `Actions` block and watch action. Derived status cache теперь различает `idle`, `running`, `waiting approval`, `waiting user`, `error` and `closed` from native `ThreadStatus`/active flags and live turn state. Running path-backed MAv2 agents больше не перехватываются отдельным history-cell выводом: они открываются в том же picker/workbench window. Lifecycle actions now include confirmed `interrupt one` for owned running/waiting path-backed sub-agents, root/subtree-owner queue-only `send-message`, root/subtree-owner trigger-turn `follow-up` for idle owned path-backed descendants, and confirmed `close one` for owned path-backed spawned descendants. `interrupt one` shows the cached previous/current status in confirmation and success copy, submits existing `turn/interrupt` through `SubmitThreadOp`, then refreshes the row from app-server liveness after success. `send-message` uses experimental app-server `agent/message/send`, `ThreadManager::queue_inter_agent_message` and encrypted `InterAgentCommunication { trigger_turn: false }`; root and path-backed subtree-owner workbenches show it only for owned path-backed descendants, and the server repeats ownership/path-backed author validation before native queue-only delivery without starting a turn. `follow-up` uses experimental app-server `agent/followup/send`, `ThreadManager::send_inter_agent_followup` and encrypted `InterAgentCommunication { trigger_turn: true }`; root and path-backed subtree-owner workbenches show it only for idle owned descendants, and the server repeats ownership/status/path-backed author validation before native delivery. `close one` uses experimental app-server `agent/close`, `ThreadManager::close_agent_from_workbench` and native `AgentControl::close_agent`; it marks the target spawn edge closed, shuts down the live target subtree and keeps the thread available for replay/resume. Не хватает historical `Ctrl+T` hotkey parity because `Ctrl+T` is the native transcript overlay, dismiss-only hiding, retry, stop-all actions и explicit connect/switch UX из fork docs.

## fork/140 OpenClaude-inspired target

OpenClaude `background-agents-tasks.snap` используется как UX reference для будущего качества workbench, но не как источник архитектуры. Полезные принципы: scan-first list, selected detail с recovery anchors, понятные status/kind/label/current activity, bounded recent activity, отдельные lifecycle actions and destructive confirmations.

Для Codex реализация должна оставаться проекцией native sources:

- lineage and identity: `SessionSource::SubAgent(ThreadSpawn)`, `AgentPath`, `agent_nickname`, `agent_role`, `thread_note`;
- runtime status: `AgentControl`, `AgentStatus`, app-server `ThreadStatus` and active flags;
- activity: `ThreadItem`, `ThreadEventStore`, bounded summaries; legacy `agent_status_feed` сохранён только как test/reference surface после объединения picker path;
- workdir/model/detail context: app-server thread/session metadata where available;
- selection/watch: existing `SelectAgentThread`, not direct user input into MAv2 child threads.

Team/status UX входит в эту feature как observational projection поверх тех же native sources. Planner/implementer/verifier-style team labels должны быть обычными `agent_role`, а status должен выводиться из `ThreadStatus`/active flags and bounded activity events. OpenClaude team file, mailbox, task owner/busy files and pane controls не переносятся.

Первый implementation slice реализован как observational enhancement of existing `/agent` picker, not a new registry or protocol surface. It uses `AgentNavigationState` / `AgentPickerThreadEntry`, native derived status cache, bounded `ThreadEventStore` item summaries and existing `SelectAgentThread` action. Второй локальный срез убрал running path-backed MAv2 bypass: `/agent` теперь открывает единый picker/workbench window и для agents с canonical `agent_path`. Третий узкий срез добавил selected detail recent activity без raw transcript, raw command output, raw reasoning или tool JSON. Четвёртый срез заменил ambiguous running/closed booleans на derived `AgentPickerThreadStatus`, который обновляется через `thread/read`, `ThreadStatusChanged`, live turn state and close events. Пятый срез гидрирует selected detail anchors из existing `Thread` metadata: `thread_note`/`agent_path` from `SessionSource::SubAgent(ThreadSpawn)`, `cwd` and `model_provider`. Шестой metadata slice добавляет model/reasoning/service tier только из native TUI `ThreadSessionState`; replay-only rows and plain `thread/read` rows leave those fields absent instead of guessing. Седьмой detail slice добавляет token anchors from latest per-thread `ThreadTokenUsageUpdated` notification in `ThreadEventStore`; missing usage renders no token line and account-wide `/usage` data is not reused. Восьмой срез добавляет `interrupt one` as a confirmed TUI action over existing `SubmitThreadOp { op: AppCommand::interrupt() }` / app-server `turn/interrupt`; TUI preflight denies main/root/self/missing-path/closed/idle/error and outside-subtree targets before showing or submitting the action, and successful confirmation refreshes row status through the existing app-server liveness path. Девятый UI-polish slice отделяет selected-detail `Inspect` anchors от `Actions`, сохраняя те же native rows/actions instead of adding a new control surface. Десятый prompt/context slice добавляет bounded `Prompt:` anchor from app-server `Thread.preview`, hydrated through the existing `thread/read`/`ThreadStarted` path; it does not call `thread/read(includeTurns=true)`, scan child `UserMessage` items or expose encrypted `InterAgentCommunication`. Одиннадцатый context slice добавляет receiver-matched `Context:` lines from already-buffered `CollabAgentToolCall.prompt` for `SpawnAgent` and `SendInput`, capped and whitespace-normalized; non-matching receivers and raw `UserMessage` items stay hidden. Двенадцатый progress slice добавляет bounded `Plan:` anchor from latest per-thread `TurnPlanUpdated` notification; it renders completed/total and current in-progress step only, ignores explanation and does not use `ThreadItem::Plan`, `PlanDelta`, raw turns or transcript text. Тринадцатый lifecycle slice добавляет root-workbench `send-message`: `/agent` shows `Send message` for eligible path-backed live targets, opens `Message agent`, and submits experimental app-server `agent/message/send` to `ThreadManager::queue_inter_agent_message`, which delegates to native `AgentControl::send_inter_agent_communication` with `trigger_turn=false`. Четырнадцатый team/status slice добавляет bounded header summary over the same picker cache: sub-agent total, running, waiting, error and closed counts, excluding the main thread and without adding a team store. Пятнадцатый metadata slice добавляет stable `Created:`/`Updated:` anchors из native `Thread.created_at`/`Thread.updated_at`, форматированные как UTC timestamps; это не live elapsed timer и не требует дополнительного ticking UI. Шестнадцатый lifecycle slice добавляет confirmed `close one`: `/agent` shows `Close <agent>` only for owned path-backed spawned descendants, opens destructive confirmation and submits experimental app-server `agent/close` to `ThreadManager::close_agent_from_workbench`, which validates descendant ownership and delegates to native `AgentControl::close_agent`. Семнадцатый lifecycle slice добавляет root-workbench trigger-turn `follow-up`: `/agent` shows `Follow up <agent>` only for idle eligible path-backed descendants, opens `Follow up with agent`, confirms `Start a follow-up turn?` and submits experimental app-server `agent/followup/send` to `ThreadManager::send_inter_agent_followup`, which reuses native encrypted inter-agent communication with `trigger_turn=true`. Восемнадцатый lifecycle slice расширяет `follow-up` на path-backed subtree-owner workbench: non-root active agent can follow up idle descendants in its own `AgentPath` subtree, while self, sibling, root, pathless owner/target and busy/error/closed targets are denied in TUI and server guards. Девятнадцатый lifecycle slice расширяет queue-only `send-message` на path-backed subtree-owner workbench: non-root active agent can queue encrypted input only to descendants in its own `AgentPath` subtree, while self, sibling, root, pathless owner/target and error/closed targets are denied in TUI and server guards. `stop all`, retry/skip and dismiss completed rows remain deferred.

## Lifecycle action contract

Subagent Workbench actions must be native Codex projections over MAv2 `AgentControl`, tool handlers, thread/session lineage and TUI thread selection. The workbench must not copy OpenClaude task files, team storage, mailbox files, tmux/iTerm controls, workflow retry/skip files or task ownership metadata.

| Action family | First implementation | Native integration point | Contract |
| --- | --- | --- | --- |
| `view` / `watch` / `select` | Allowed | `/agent` picker, `AgentNavigationState`, `SelectAgentThread` | Safe observational action. It changes the watched TUI thread only; it must not inject user input into the child thread and must keep `/agents` reserved for role templates. |
| `send-message` | Implemented for root/subtree-owner workbench eligible targets | Experimental app-server `agent/message/send` -> `ThreadManager::queue_inter_agent_message` -> `AgentControl::send_inter_agent_communication`; model tool path remains MAv2 `send_message` / `MessageDeliveryMode::QueueOnly` | Queues encrypted `InterAgentCommunication { trigger_turn: false }` for one path-backed descendant without starting a turn. UI copy says `queued`; TUI preflight denies main/root/missing-path/self/sibling/closed/error/pathless-owner targets. It must not use `turn/start`, `turn/steer`, trigger-turn follow-up or raw app-server `Op` submission. |
| `followup_task` | Implemented for root/subtree-owner workbench idle eligible targets | Experimental app-server `agent/followup/send` -> `ThreadManager::send_inter_agent_followup` -> `AgentControl::send_inter_agent_communication`; model tool path remains MAv2 `followup_task` / `MessageDeliveryMode::TriggerTurn` | Queues encrypted `InterAgentCommunication { trigger_turn: true }` and starts the target when native capacity permits. UI copy says `starts a turn`; TUI preflight allows only idle path-backed descendants of the current workbench owner, and server preflight repeats ownership/status/path-backed author checks. |
| `interrupt one` | Implemented for TUI root/subtree workbench after confirmation | Existing TUI `SubmitThreadOp` -> app-server `turn/interrupt` -> `Op::Interrupt`; model tool path remains MAv2 `interrupt_agent` / `AgentControl::interrupt_agent` | May target one non-root spawned MAv2 agent when TUI ownership/status preflight passes. The UI action is explicit confirmation, includes the cached status before interrupt, does not close/delete the thread and must not masquerade as close/kill. Successful confirmation refreshes row status from app-server liveness. This is a TUI cached previous-status display, not an app-server `InterruptAgentResult.previous_status` payload. |
| `wait` / `result` | Allowed as observation only | MAv2 `wait_agent`, mailbox/status notifications, bounded detail summaries | Workbench may show waiting/result state and bounded final/status summaries. It must not expose raw transcript, encrypted content, raw reasoning or long tool output, and it must not promise OpenClaude-style task result files. |
| `close one` | Implemented after destructive confirmation | Experimental app-server `agent/close` -> `ThreadManager::close_agent_from_workbench` -> `AgentControl::close_agent`; persisted spawn-edge `Closed` status and `shutdown_agent_tree` remain native runtime behavior | May target one owned path-backed spawned descendant. The UI says the target spawn edge is marked closed, the live target and descendants are shut down, and replay/resume remains available. TUI preflight denies main/root/self/missing-path/already-closed and outside-subtree targets. |
| `dismiss` | Deferred | No separate native UI-hide source selected | Dismiss-only UI hiding is deferred because hiding replayable rows can conflict with recovery and would otherwise need a parallel workbench hidden-row cache. |
| `retry` | Deferred | No native MAv2 retry primitive selected | Retrying must be a new native follow-up/spawn contract, not an OpenClaude workflow retry/skip clone. It needs idempotency, cwd/config inheritance and transcript reference rules before UI. |
| `stop all` | Deferred | No broad workbench primitive selected | Bulk interruption/shutdown is high-risk. It needs root-only or scoped subtree policy, count/status summary, confirmation wording and negative tests before any TUI action. |

Ownership rules for lifecycle actions are path-based, not file-based. Root may observe all agents in its root-scoped `AgentControl` tree, may interrupt one spawned non-root agent, may close one spawned non-root descendant, may queue a message to one eligible spawned non-root agent and may start a follow-up turn for one idle eligible spawned non-root agent. A non-root agent may interrupt, close, queue a message to or follow up descendants in its own `AgentPath` subtree. Sibling and ancestor targets are denied. Self-interrupt/self-close/self-message/self-follow-up is denied; the agent should return or ask its parent. Root itself is not a spawned agent and must not be an interrupt/close/message/follow-up target.

Confirmation wording must be explicit and state the target and scope. Current implemented wording for `interrupt one`: title `Interrupt this agent?`, target subtitle `{label} · {agent_path} · current status: {status}`, rows `Cancel` and `Interrupt agent`, action copy `Current status: {status}. Stop the current turn only. It does not close or delete the thread.`, and success copy `Interrupt requested for <agent> (previous status: <status>).` Current implemented wording for `send-message`: action label `Send message`, prompt title `Message agent`, placeholder `Write a message for this agent`, success copy `Message queued for <agent>.`, empty-input error `Cannot send an empty agent message.`, and unsupported-runtime diagnostic `Agent messaging is not supported by the connected app-server. Restart Codex from this fork build.` Current implemented wording for `follow-up`: action label `Follow up`, prompt title `Follow up with agent`, placeholder `Write the next task for this agent`, confirmation title `Start a follow-up turn?`, action row `Start follow-up`, action copy `Queue an encrypted follow-up and start this agent when capacity is available.`, success copy `Follow-up started for <agent>.`, hint `The agent may request approvals under its existing sandbox.`, empty-input error `Cannot send an empty agent follow-up.`, and unsupported-runtime diagnostic `Agent follow-up is not supported by the connected app-server. Restart Codex from this fork build.` Current implemented wording for `close one`: title `Close this agent?`, target subtitle `{label} · {agent_path} · current status: {status}`, rows `Cancel` and `Close agent`, action copy `Current status: {status}. Mark this spawn edge closed and shut down the live target and descendants.`, success copy `Closed <agent> (previous status: <status>).`, resume hint `The thread remains available for replay and native resume paths.`, and unsupported-runtime diagnostic `Agent close is not supported by the connected app-server. Restart Codex from this fork build.` Future stop-all wording must list the number of affected running/waiting agents and require a destructive confirmation token or equivalent deliberate action.

Permissions, security and resume impact: lifecycle actions must not widen cwd, workspace roots, sandbox, approval policy, MCP tools or model/provider settings. Send/followup must preserve encrypted inter-agent content semantics. Wait/result/detail must stay bounded and redacted. Close/resume must preserve old sessions and persisted thread-spawn edges; missing `agent_path`, `thread_note`, cwd or role metadata must render as a controlled empty state rather than blocking watch/select.
