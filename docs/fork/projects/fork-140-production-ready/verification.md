# Production-ready verification plan

Verification is slice-based. A slice is not complete until docs, runtime behavior, tests, generated artifacts and an independent audit agree.

## Required gates for every slice

| Gate | Command or evidence |
| --- | --- |
| Whitespace/diff hygiene | `git diff --check` |
| Rust formatting | `cd codex-rs && just fmt` after code changes |
| Focused crate tests | `cd codex-rs && just test -p <crate> <filters>` |
| TUI snapshots | `cd codex-rs && just test -p codex-tui <snapshot filters>` and `cargo insta pending-snapshots --workspace-root .` |
| Protocol/schema | `cd codex-rs && just write-app-server-schema` when app-server protocol changes, followed by focused protocol/schema tests |
| Docs consistency | Feature doc, project `design.md`, project `verification.md` and research backlog updated in the same slice |
| Audit | Independent sub-agent or manual audit records High/Medium findings as fixed or explicitly approved |

## Slice-specific minimum matrix

| Slice | Minimum production checks |
| --- | --- |
| Policy enforcement substrate | Positive/negative tests for root, self, descendant, sibling, pathless author/target, `read_only`, allowed action, denied action, MCP allow/deny, and resume/restart of effective policy. |
| Role tool policy v2 | Parser/config tests for allow/deny syntax, `spec_plan` filtering for direct, deferred, MCP, hosted, Code Mode and `tool_search`, blocked-dispatch tests, stale-id diagnostics, generated schema tests if protocol changes. |
| Role import/authoring v2 | Markdown/frontmatter/persona import tests that produce native role config, invalid input diagnostics, no parallel registry, TUI staged-control snapshots, reload/current-vs-next-turn contract tests. |
| Workbench visibility/lifecycle v2 | Dismiss replay/resume tests, retry inheritance tests, stop-all partial failure tests, destructive confirmation snapshots, ownership denial tests, pathless denial tests, explicit connect/switch snapshots and Ctrl+T transcript-to-Agent-Window routing tests. |
| Cross-feature acceptance | Role policy + workbench action, provider/model + retry, MCP allow/deny + role tool policy, resume/restart with dismissed/retried/closed agents, 12-agent stress where feasible. |

## Current test surfaces to reuse

- Core multi-agent tests live near `codex-rs/core/src/tools/handlers/multi_agents_tests.rs`.
- Tool-selection and planner tests live around `codex-rs/core/src/tools/spec_plan*.rs` and role-template tests.
- App-server v2 suite lives under `codex-rs/app-server/tests/suite/v2/`.
- TUI workbench and role-template snapshots live under `codex-rs/tui/src/**/snapshots/` and app/chatwidget tests.

## Current gaps to close before completion

- Verified production contracts for Agent Window `dismiss`, `retry` and `stop all` are implemented over native thread metadata/session source, app-server `agent/*` methods and `AgentControl` paths. Ctrl+T Agent Window parity is implemented only as repeated Ctrl+T from native transcript overlay.
- `read_only` role enforcement is implemented through native permission config, direct app-server MCP execution now respects role-level `[tool_selection]` allow/deny, explicit workbench action allow/deny is implemented through persisted `SubAgentActionPolicySnapshot`, `agentRole/actionPolicy/set` writes native user role TOML for future spawns/config refresh boundaries, project-local role loading is trust-gated through native project config layers, and `.agents` remains protected read-only metadata under workspace-write sandbox policy. MCP allow/deny management intentionally uses the generic native `[tool_selection]` UI/API instead of a separate MCP-only policy surface.
- External app-server role tool-policy write is implemented as whole-policy `agentRole/toolSelection/set` for discovered user role TOML files. Partial patch/versioned writes, built-in role editing and external `config_file` writes remain outside the current contract.
- Markdown/frontmatter/persona import that compiles into native role TOML/config is implemented through the existing `/import` external-agent migration flow and exposed from `/agent-roles`; no runtime markdown loader is claimed.
- Role authoring staged controls now include current-model create, inline existing user-role TOML editing, existing user-role current-model update, existing user-role current model/provider-only update, existing user-role current-reasoning update, catalog-backed model/provider/reasoning picker controls, current-tools create and separate discovered-user-role allowed/denied tool editing through parser-validated native TOML drafts.
- Inline existing user-role TOML editing is verified by `just test -p codex-core user_agent_role_template_draft_from_file_preserves_raw_native_toml` and `just test -p codex-tui agent_role_template_edit_prompt_submits_existing_native_toml_draft agent_role_templates_popup_snapshot agent_role_templates_popup_runtime_catalog_snapshot`, with only intentional `/agent-roles` snapshot updates accepted.
- Built-in `reviewer` is implemented as a bundled native role with `default_permissions = ":read-only"`; no separate runtime enum or profile registry is introduced.
- Final cross-feature acceptance now has representative focused runs and generated artifact review evidence. Completion still requires closing or explicitly accepting any remaining High/Medium independent audit findings.
