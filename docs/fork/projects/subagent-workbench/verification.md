# Subagent Workbench verification

## Required checks

| Surface | Required verification |
| --- | --- |
| Runtime source map | Focused core tests around MAv2 `spawn`, `list_agents`, `thread_note`, cwd and lifecycle status. |
| App-server projection | `thread/read`, `thread/list`, loaded thread list and `ThreadStatusChanged` tests if new fields or status handling are added. |
| TUI list/detail | `codex-tui` snapshots for the implemented `/agent` picker detail; future snapshots for empty, running path-backed MAv2, waiting, completed/interrupted/error, replay-only and narrow-width states. |
| Privacy/boundedness | Tests proving command output, raw reasoning, encrypted messages and long prompts are bounded or hidden. |
| Lifecycle actions | Positive/negative tests for select/watch, queue-only `send-message`, trigger-turn `follow-up`, `interrupt one` and `close one`; root/subtree/sibling/self ownership must be explicit. Deferred actions require contract tests before UI enablement. |
| Docs | `git diff --check -- docs/fork/features/subagent-workbench.md docs/fork/projects/subagent-workbench docs/fork/research/0.140.0/openclaude-agent-ux-runtime*.md`. |

## Scenario matrix

| Scenario | Expected result |
| --- | --- |
| No sub-agents | Workbench shows an empty state without changing `/agent` command semantics. |
| Two running MAv2 agents | Rows show stable labels, status, bounded current activity and selectable thread targets. |
| Waiting on approval/user input | Status derives from app-server `ThreadStatus::Active` flags and does not masquerade as idle. |
| Completed/interrupted/errored | Rows remain stable enough for replay/detail; actions are limited according to lifecycle contract. |
| Role template spawn | Row/detail show role/nickname from native metadata without duplicating the role registry. |
| Thread note present | Note appears as bounded recovery clue. Missing note renders empty state. |
| Different cwd | Detail shows cwd/workdir if available; no permission or workspace root widening occurs. |
| Loaded session model/reasoning | Detail shows model, reasoning effort and service tier only when the current TUI has native `ThreadSessionState`; replay-only rows do not guess those values. |
| Token usage notification | Detail shows bounded token anchors from the latest per-thread `ThreadTokenUsageUpdated`; missing usage renders no token line. |
| Encrypted or unavailable task message | Detail shows a controlled placeholder, not decrypted or guessed content. |
| Long output/reasoning | UI shows bounded summaries and never dumps raw output/reasoning. |
| `/agents` command | Still opens role template management, not the workbench. |

## Known gaps after first slice

- No first-class workbench read model exists beyond the fallback `/agent` picker projection; `Inspect`/`Actions` are currently selected-detail presentation sections, not a separate workbench data model.
- Prompt/context preview is limited to app-server `Thread.preview` and receiver-matched buffered `CollabAgentToolCall.prompt`. Raw turns, child `UserMessage` items, rollout operations, other receivers and encrypted inter-agent content stay intentionally out of scope.
- Plan progress is limited to latest per-thread `TurnPlanUpdated` notification. Raw `ThreadItem::Plan`, `PlanDelta`, explanation text and historical transcript reconstruction stay intentionally out of scope.
- Stable `Created:`/`Updated:` thread timestamps are implemented from native thread metadata. Live elapsed age and current-work age remain unresolved because spawned age and active-turn age are different fields and would need a ticking UI contract.
- App-server top-level projection for `thread_note`/`agent_path` may be insufficient; avoid schema changes until current sources are proven inadequate.
- `interrupt one` is implemented for the first TUI slice with cached pre-interrupt status copy and post-action liveness refresh. It intentionally does not add an app-server previous-status payload; the displayed previous status is the TUI cache value before submitting `turn/interrupt`.
- Queue-only `send-message` is implemented for root/subtree-owner eligible path-backed descendants through `agent/message/send` and `ThreadManager::queue_inter_agent_message`; pathless non-root owners, self, siblings, root, error and closed targets remain denied. Trigger-turn `follow-up` is implemented for root/subtree-owner workbench through `agent/followup/send` and `ThreadManager::send_inter_agent_followup`; pathless non-root owners, self, siblings, root and unavailable targets remain denied. `close one` is implemented through `agent/close` and native `AgentControl::close_agent`; dismiss-only hiding, retry and stop-all remain intentionally deferred from the workbench UI until their native contracts and destructive/permission tests are specified.
- Token detail is limited to latest per-thread `ThreadTokenUsageUpdated`; historical replay without token notifications and account-wide usage are intentionally out of scope for the workbench detail. Current slices add derived status, `thread_note`, cwd, model provider, session-backed model/reasoning/service tier, token usage anchors and bounded activity from native thread metadata, `ThreadSessionState` and buffered notifications/items.
- `stop all` UX is intentionally deferred until ownership and confirmation tests are specified.
- Historical `Ctrl+T` SAW hotkey parity remains intentionally deferred because `Ctrl+T` is the native transcript overlay. The current implementation improves the `/agent` workbench surface instead of stealing that keybinding.
