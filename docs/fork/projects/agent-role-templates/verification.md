## Coverage

Core tests подтверждают, что TUI не получает отдельный role registry: список строится из `Config.agent_roles` и built-ins, user role с именем built-in role становится active, built-in entry остаётся видимой как shadowed, а file-backed user role получает parser-validation diagnostic from the existing TOML role parser. Typed availability projection теперь проверяет session-boundary contract: user templates are `NewSessionsOnly`, active built-ins are `BuiltIn`, and shadowed built-ins are `ShadowedBuiltIn`; это связано с native reload foundation: `reload_user_config_layer` and `refresh_runtime_config` rebuild `Config.agent_roles` from current config layers, TUI wizard calls the existing app-server reload path after successful create, and a new foreground turn rebuilds `spawn_agent.agent_type` schema from the refreshed role catalog. Этот parser-validation path теперь также ловит invalid or duplicate `[tool_selection] allowed_tools`, so role listing and TOML draft creation fail before spawn/config rebuild. Create-flow coverage подтверждает, что wizard пишет валидный TOML draft в native `$CODEX_HOME/agents/`, includes only a commented `[tool_selection] allowed_tools` hint by default, rejects non-normalized role names before writing, returns success to dispatcher for reload, and still keeps the old name-helper path for compatibility. Inline editor coverage подтверждает, что existing user-role TOML is loaded as raw text, validated before opening, and submitted through the same update path without losing comments/order by default. Tool staged-control coverage подтверждает, что catalog-assisted authoring creates/edits native `[tool_selection] allowed_tools` and `denied_tools` through the same editable TOML draft path, and deny editing preserves the existing allowlist. Field-source projection покрывает declaration fields from effective `AgentRoleConfig` and TOML fields from the native role file/bundled config; bounded field provenance показывает только доказуемые sources: config layer, role-file metadata, effective role-file runtime fields, selected `config_file` inheritance/override detail at file granularity, discovered `$CODEX_HOME/agents` files, built-in bundle files and native loader trace for inherited/overridden metadata fields. Config-file origin projection покрывает `$CODEX_HOME/agents`, external `config_file` and built-in bundle roles; declaration origin projection покрывает native config layer sources for `agents.<role>.description`, `config_file` and `nickname_candidates` where `ConfigLayerStack.origins()` can prove them. Role-lock projection теперь покрывает `model`, `model_provider`, `model_reasoning_effort`, `service_tier`, developer instructions presence and declared `[tool_selection] allowed_tools` / `denied_tools`. Runtime in-use projection покрывает только existing TUI thread metadata: `AgentNavigationState` excludes the primary thread, ignores empty roles, counts known non-primary threads by role/status and marks current viewed role when thread evidence exists. Security summary projection покрывает declared `approval_policy`, `default_permissions` and custom `[permissions]` profile count; `sandbox_mode` and `[sandbox_workspace_write]` use the same raw native TOML presence path. Subsystem summary projection покрывает counts/presence for declared `[mcp_servers]`, `[hooks]`, `[skills.config]` and `[apps]` without exposing command/env/secret/payload details. TUI snapshots cover selected detail с declaration fields, config origin, editable native fields, bounded field provenance, validation status, provider-aware role-lock summary, runtime in-use summary, declared tool-selection allowlist/denylist, security summary, subsystem summary, runtime binding, create/user active/built-in active/built-in shadowed rows, plus native TOML draft authoring prompt.

OpenClaude-style markdown/frontmatter import is available from role management only as a link to the existing external-agent migration compile-to-native TOML flow. Basic user-vs-built-in active/shadowed state, typed availability/session-boundary projection, bounded field-source provenance, per-field runtime TOML inherited/overridden detail, config-file origin, config-layer declaration origins, loader-derived metadata inheritance/override evidence, runtime in-use evidence, native `agent_roles` reload via config refresh, automatic wizard-triggered reload through existing app-server config reload, next-foreground-turn spawn tool schema refresh, parser-validated TOML draft creation, inline existing-role TOML editor, current-model create/update, current model/provider-only update, current-reasoning update, catalog-backed model/provider/reasoning picker controls, clear-model staged action, current-tools create and discovered user-role allow/deny tool editing уже реализованы. Immediate schema rewrite inside an already running model turn is intentionally not claimed; Codex rebuilds model-visible tool specs for the next foreground turn.

Role-level tool-selection runtime enforcement remains in `agent-role-tool-selection`. Runtime contract, stale-id diagnostics, cold resume verification, blocked-dispatch guard, app-server catalog read, read-only `/agent-roles` current-thread catalog reference, parser-validated TOML draft authoring, catalog-assisted create and discovered user-role allow/deny editing exist through the native role/tool-selection path; external app-server write/management API is tracked as a separate whole-policy contract.
