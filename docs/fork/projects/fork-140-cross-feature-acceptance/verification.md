## Remaining accepted gaps

- Dedicated MCP-only allow/deny management UI/API is intentionally not part of the production-ready contract. MCP allow/deny is managed through the generic native `[tool_selection]` surface, `/agent-roles` catalog-assisted authoring and `agentRole/toolSelection/set`, then enforced by `spec_plan`, `ToolRegistry` and direct app-server MCP call checks.
- `mcp-on-demand-discovery` still does not add model-visible MCP create/refresh; it verifies existing app-server refresh instead.
- Runtime markdown/frontmatter loader remains outside the current implemented contract; markdown/frontmatter is import-only and compiles to native TOML. Role-template authoring now includes existing-user-role TOML inline editing, current model/provider-only update and catalog-backed model/provider/reasoning picker controls through the native parser/write/reload path.
- Stop-all partial-failure aggregation is covered at the return-contract level and TUI-visible partial result copy is covered by focused `codex-tui` tests; broader real shutdown-failure injection remains lower-priority resilience coverage.
- Full manual TUI smoke with a rebuilt installed fork binary remains release acceptance, not a local branch merge gate.
