## Verification gates

- Every feature must have a propagation matrix naming native source of truth, producers, consumers, persistence/resume behavior, app-server/TUI projections, generated artifacts and intentionally unaffected surfaces.
- UI changes require `insta` snapshots and review through normal cargo-insta flow, not manual `.snap.new` renames.
- Runtime changes require focused Rust tests in the owning crate and a regression check for the existing upstream path most likely to break.
- App-server or schema changes require generated schema updates, protocol tests and compatibility notes.
- Permissions, cwd, sandbox, MCP, tool registry, persistence or resume changes require positive and negative security/ownership checks.
- Coverage target is near 100% for new/changed behavior. Any uncovered area must be named in the feature project's `verification.md` with a reason.

## Current blockers and decisions

- Historical caution: the worktree contained many non-doc changes from provider/model work, so broad agent work was paused until artifact and current-state audits completed. Those audits are now captured below; future edits should still keep feature scopes isolated.
- `agent-role-tool-selection` is not just UI. It needs a real config/runtime contract because filtering must happen before `tool_search`, Code Mode and `ToolRegistry` dispatch.
- `agent-role-wizard` must not invent markdown/frontmatter storage; first version must use native TOML role files.
- Team/status layer must not copy OpenClaude `.claude/teams`, file mailbox, tmux/iTerm pane controls or task ownership files.
- Lifecycle actions must not copy OpenClaude background task storage, task result files or workflow retry/skip semantics. Use native MAv2 `AgentControl`, `AgentPath`, `SubAgentActivityEvent`, thread selection and bounded thread-event summaries only.
- Current workbench lifecycle actions are intentionally narrow: confirmed `interrupt one`, queue-only root/subtree-owner `send-message`, root/subtree-owner trigger-turn `follow-up` and confirmed `close one`. `interrupt one` uses explicit confirmation copy, cached pre-interrupt status display and preflight for main/root/self/missing-path/idle/closed/error/outside-subtree targets, then refreshes the target row via the existing app-server liveness path after success. The previous-status copy is intentionally TUI-cache based because app-server `turn/interrupt` does not return MAv2 `InterruptAgentResult`.
- `send-message` is implemented only as queue-only messaging for root or path-backed subtree-owner workbenches: `agent/message/send` -> `ThreadManager::queue_inter_agent_message` -> `AgentControl::send_inter_agent_communication`, encrypted `InterAgentCommunication { trigger_turn: false }`, action copy `Message queued for <agent>.` It must not be changed to `turn/start`, `turn/steer`, raw `Op::InterAgentCommunication` from app-server, trigger-turn follow-up or any OpenClaude task mailbox.
- `follow-up` is implemented only as trigger-turn messaging for root or path-backed subtree-owner workbenches: `agent/followup/send` -> `ThreadManager::send_inter_agent_followup` -> `AgentControl::send_inter_agent_communication`, encrypted `InterAgentCommunication { trigger_turn: true }`, action copy `Follow-up started for <agent>.` It must not be changed to queue-only messaging, direct `turn/start`, `turn/steer`, raw `Op::InterAgentCommunication` from app-server or any OpenClaude task mailbox.
- `close` is not equivalent to dismiss: implemented `close one` deliberately uses native `AgentControl::close_agent` through `ThreadManager::close_agent_from_workbench`, marks spawn-edge state closed, shuts down descendants and keeps replay/resume available. Dismiss-only row hiding remains deferred because it would need a separate native source of truth.
